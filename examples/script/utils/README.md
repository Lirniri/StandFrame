# Utils

**English** | [Русский](README.ru.md)

Things built on natives, in `Atdar.util.game`: what several natives do together. Graceland is the main one.

The folders follow the code: `players/user/` is `Atdar.util.game.players.user` (the local player: Graceland works on
him only, it takes his id and his ped), `entity/` is `Atdar.util.game.entity`, `world/` is `Atdar.util.game.world`, `tools/` is `Atdar.util.game.tools`, `data/` is `Atdar.util.game.data`.

## Graceland: a fall from any height

```pluto
local graceland = Atdar.util.game.players.user.graceland

graceland.enable()
if graceland.is_enabled() then ... end
graceland.disable()
```

The player falls without dying and steers the fall with the stick. It works like this (found by trying in the game):

1. After `ragdoll_distance` metres of a fall (12 by default) the game ragdolls the player.
2. While he is ragdolling, `GIVE_PLAYER_RAGDOLL_CONTROL` lets the stick steer the ragdoll.
3. A ragdoll hitting the ground at fall speed kills. So `landing_time` seconds before the ground (0.5), at the speed it
   has, the ragdoll is ended: the player stands up in the air, keeps his speed, faces where `facing` says (the camera
   by default) and lands on his feet without damage.
4. After the touch the protection stays 0.6 s more: the game decides about the landing a moment later.
5. A ragdoll that hits a wall in the air is ended the same way (`wall_protection`), and the rest of the fall goes without
   a ragdoll, so without steering.

#### Ragdoll

| Setting | Default | What it does |
|---|---|---|
| `set_steering(toggle)` | `true` | Whether a ragdoll starts in a fall after the ragdoll distance, and the stick steers it (when `set_air_control` is on). Off: no ragdoll in a fall at all, no death from it; the stick then steers the plain fall through the memory |
| `set_ragdoll_distance(metres)` | `12` | The fall after which the ragdoll starts (5 at least, a smaller value is raised) |
| `set_safe_landing(toggle)` | `true` | Off: the ragdoll lands as it is, and a long fall kills |
| `set_landing_time(seconds)` | `0.5` | How long before the ground the ragdoll is ended: 27 m at 55 m/s, 6 m at 12 m/s (0.1 at least) |
| `set_wall_protection(toggle)` | `true` | A ragdoll that flies into a wall (above 3 m from the ground) is ended there: the player falls the rest without a ragdoll and without damage |
| `set_facing(mode)` | `"camera"` | Where the player faces when the ragdoll is ended: `"camera"` (where the camera looks), `"start"` (the way he faced when the fall began), `"none"` (any way the ragdoll left him) |
| `set_stuck_ragdoll(ms)` | `1500` | A ragdoll that lies still this long after a landing is ended; `0` - never |

#### No ragdoll

| Setting | Default | What it does |
|---|---|---|
| `set_air_control(toggle)` | `true` | Whether the stick steers the fall: with `set_steering` on it steers the ragdoll (the ragdoll control), with it off the plain fall without a ragdoll (the flags of the game's fall task, like Stand's Graceland; the memory part reads the offsets of a build of the game). Off: no steering at all |
| `set_beast_fall(toggle)` | `true` | Puts the flag `BEAST_FALL` of the fall task in the steered fall. In the game it did not show the arms-out animation (found by trying), so the bit is not the one of that animation: `Atdar.util.game.players.user.air_control.probe_bits()` goes through the bits of the flags, one at a time, to find it. Off: the steering and the damping only. Works with `set_air_control` on, and can be switched in the middle of a fall |
| `set_flag_protection(toggle)` | `false` | A try: also uses the game's ped flags in a fall (impacts don't ragdoll the player, `NEVER_RAGDOLL` with steering off, the wall seen by `PED_HIT_WALL_LAST_FRAME`). Gives no steering |

#### Common

| Setting | Default | What it does |
|---|---|---|
| `set_debug(toggle)` | `false` | One line per fall event in the debug log |

All of them can be called from Call Function (`Atdar.util.game.players.user.graceland.set_ragdoll_distance`).

### The debug line

```
fall rag=1 can=1 cache=0 fall=1 air=1 h=250 v=22.3 F1 L0 J1 A1 hp=328 vel=5.8,2.4,-21.5 stick=-1.0,0.0 dir=-0.3,1.0
```

`rag` ragdoll, `can` what the game says about `CAN_PED_RAGDOLL`, `cache` what graceland set, `fall` falling, `air` in
the air, `h` height above the ground, `v` speed, `F L J A` the game's flags (pure fall, landing, jumping, in the air),
`hp` health, `vel` velocity, `stick` the left stick, `dir` the stick in the world (compare it with `vel`: steering works
if `vel` goes where `dir` points). The first word is the event: `fall` (every second), `AIR` and `LAND` (left or
reached the ground), `TOUCH` (the speed jumped, a touch), `RAGDOLL STARTED`, `ragdoll ended`.

### Good to know

- Stand's own Graceland can't be switched on while the player is ragdolling: turn it off before testing this one.
- A jump from 8 to about 12 m ends in a ragdoll that is ended close to the ground: that is by design (`landing_time`).
- The Beast jump animation doesn't come from `SET_BEAST_JUMP_THIS_FRAME` here: it didn't show in the game.
- `disable()` in the air does not drop the protection at once: the fall stays protected until the ground, then
  everything is given back (a stopped script releases at once). `is_enabled()` is false from the call.
- The module was run on stand-ins for the game (a simulation with a death model taken from what was seen in the game):
  every height from 3 to 250 m and 30, 60 and 240 frames a second live with the default settings. It is not the
  game: a single very long frame (0.5 s or more) near the ground can still kill.

## The player's functions

Every file of `players/user/` besides Graceland is one function of the local player, named after Stand's feature it
follows (`auto_heal`, `airwalk`, `auto_boost`, `damage`, `drunk_mode`, `exit_stop`, `freecam`, `infinite_ammo`,
`invisibility`, `levitate`, `move_freedom`, `no_collision`, `no_reload`, `auto_cancel_anim`, `air_swim`, `dont_jack_me`,
`leave_engine_running`, `no_roll_cooldown`). The ones that do something every frame are made with `ticker.make(name, tick,
release)` and share `enable()`, `disable()` and `is_enabled()`: an error in `tick` switches the function off, and `release`
gives back what it changed (also when the script stops). `ticker.config_flag(name, flag)` is the same for a config flag of
the ped held on. `no_roll_cooldown` patches the game's code, so it needs the pointer `combat_roll_patch` (see
[basics/10_memory.pluto](../basics/10_memory.pluto)); without it `enable()` gives `false` and changes nothing.

`outfit` keeps what the ped wears in `store/<script>/user/outfits/<name>.json`. In `world/` each file is one thing of the
world; `clock` is the only one that isn't a loop (`set`, `lock`, `unlock`, `set_speed`).

### After Stand-OSS: patches, rewind, physics

These follow Graceland's shape: `set_*` settings valid before and after `enable()`, `enable()` / `disable()` /
`is_enabled()`, `set_debug()`, everything given back at disable and when the script stops. **None of them is checked in
game**: the patterns, offsets and bytes are copied from Stand-OSS.

| Module | What it does |
|---|---|
| `preserve_walk_style`, `no_hair_scale`, `wheel_on_wheels` | A patch of the game's code each, made with `patch_toggle` from the registry of `natives.memory.patch` (pattern, place, bytes, the bytes that must be there before). `enable()` gives `false` and writes nothing if the pattern is not found or the code is another one; `disable()` puts the old bytes back |
| `rewind` | Every frame is written down; the held key (`set_action`) puts them back newest first, 2x after 5 s, 3x after 10 s, the camera follows (a scripted camera, given back at the end). `set_max_frames`, `set_speed_times`, `set_restore_camera`, `is_playing`, `get_frame_count`, `clear` |
| `super_drive` | A push on the driven vehicle while the key is held: `set_force`, `set_use_camera`, `set_action` |
| `super_handbrake` | The handbrake key stops the driven vehicle: `set_strength` (1 stops, less takes a part of the speed), `set_action` |
| `no_stunt_jumps` | Cancels the stunt jumps of the map every frame |
| `floppy_mode` | The player is a ragdoll pushed by the stick: `set_speed`, `set_sprint_multiplier`; not together with graceland |
| `gravity_gun` | Aim to grab a thing, the mouse wheel moves it, Attack throws it: `set_force`, `set_collision`, `set_contrived_physics`, `set_distance` |

`airwalk` was already there. `natives.memory.task` now has the whole aiTask layout (`TREE`, `get_chain`, `get_all`,
`get_info_list`, `get_state`), and `natives.memory.task_types` the numbers of the game's 531 tasks (generated by
`tools/gen_task_types.py`); `tools.task_list` is the debug view over them.

The tables in `data/` and `task_types` are generated by the scripts in `tools/` from a copy of Stand-OSS; `tools/i18n_sync.py`
reports and fills the translation files (`python tools/i18n_sync.py`, see its help).

## `Atdar.util.game.tools.states`

Asks the natives about the player and shows the difference between two moments. `info()`, `snapshot(name?)`,
`diff(first?, second?)`, `watch()`, `unwatch()`. Only natives with no parameters or with one handle are asked.
Useful to find what a menu option of another script changes: snapshot, switch it on, snapshot, `diff`.

### Handling and the current vehicle

`Atdar.util.game.vehicle` holds the handling numbers of a vehicle and the changes that hold while the player drives one.
Same shape as Graceland (`set_*`, `enable()` / `disable()` / `is_enabled()`, `set_debug()`, everything given back at
disable and when the script stops). **None of it is checked in game**: the layout of CHandlingData and the offsets are
copied from Stand-OSS (`natives.memory.handling` / `vehicle` have them in tables, `offsets`, to change without touching the code).

| Module | What it does |
|---|---|
| `handling` | `get` / `set` / `set_many` / `scale` / `set_bits` of a field by name (`mass`, `drive_bias_front`, `boat.keel_sphere_size` ...), `reset` / `reset_model` / `reset_all`; holders keep two users of one field apart |
| `on_current` | The helper the rest is built on: `create(name, { only / except kinds, change, undo, frame })` gives `enable`, `disable`, `refresh`, `store[model]`; done when the player drives an allowed vehicle, undone when he leaves or changes it |
| `drift_mode` | Stand's drift tune and flags, with presets (`stand`, `loose`, `grippy`), `set_value` per number, `FLAG` bits; the grip follows the speed |
| `lessen_burnouts` | `low_speed_traction_loss_mult` taken down |
| `heli_stabilisation` | No auto stabilisation of a helicopter (lift of the nose, pitch / roll / yaw stabilise, wind) |
| `gravity` | The gravity of the vehicle as a multiple of the normal one, through Stand's `entities.set_gravity_multiplier` |
| `drive_on_water` | An invisible block under the surface; single player, the pitfalls of Stand's version are kept and listed in the file |
| `forge_model` | The model info of the vehicle gets another hash; risky, single player, written back by pointer |

One handling data belongs to every vehicle of a handling name, so a change reaches all of them until it is given back:
each user of a field is a *holder*, the last holder wins, and letting go brings back the value of the one before it, or the
original. `natives.memory.holds` is the same idea for a change of the game's code (the first holder makes it, the last
release undoes it). In the menu: Vehicle > Handling.
